# Source and conversion

The source is [`datacharmer/test_db`](https://github.com/datacharmer/test_db) at commit `e324b56193ca506ab7cc1ab143a9153d8c4535d7`. Its `employees.sql` header identifies the Employees sample, credits MySQL AB (2007/2008), Fusheng Wang and Carlo Zaniolo (original data), Giuseppe Maxia (current schema), and Patrick Crews (XML-to-relational conversion), states CC BY-SA 3.0 Unported, and says the data is fabricated. The exact upstream files and SHA-256 values are in `manifest.json`; CI fetches them at that commit and verifies every hash before conversion. The full upstream dumps are not committed here. The source attribution and license notice are preserved in `UPSTREAM-NOTICE.txt`.

The browser edition selects employee IDs 10001 through 11000 inclusive, plus all distinct IDs from the source's 24 `dept_manager` rows, for 1,024 employees. It includes the source's nine departments and every `dept_manager` row, plus all `dept_emp`, `titles`, and `salaries` rows whose `emp_no` is in the selected set. The result contains 9 departments, 1,024 employees, 24 manager assignments, 1,127 department-history rows, 1,524 title-history rows, and 9,876 salary-history rows. Referential checks ensure the selected subset is closed over its employee and department foreign keys.

The converter reads the upstream multi-statement MySQL `INSERT` dumps directly, including all three salary shards, and builds six SQLite tables with the source primary keys, department-name unique constraint, and foreign keys. It defines the two source views `dept_emp_latest_date` and `current_dept_emp`; no additional rows are generated. `scripts/rebuild-source.py --check` rehashes every pinned source file, rebuilds in temporary storage, checks SQLite integrity and foreign keys, compares complete logical schema and row contents against the committed gzip fixture, and verifies the selected row counts. SQLite's file bytes may differ by SQLite library version; the gzip input hash, decoded database hash, and logical database contents are checked separately.

Dates remain ISO date text, salaries remain source integer values, and no currency is inferred because the upstream schema does not declare one. MySQL `ENUM('M','F')` is represented as checked text. `CHAR(4)` department codes retain their native short values as stored by the source dumps. The sample does not include the full upstream 300,024 employees or their full history, and must not be represented as the complete Employees database.
